一、MapReduce的简单流程

1）输入数据（Splitting）

将数据分组，划分为 M 片（16-64MB）

2）主节点分配任务（Master）

调度：分配 M 个 Map 任务和 R 个 Reduce 任务给空闲的工作节点，全程监控进度

3）Map任务 - 统计（先）

Map 节点读取数据块，解析成键值对（key-value），传给用户定义的 Map 函数，生成中间键值对（比如单词计数里的(单词, 1)）—— 表示该数据块为单词类，算为1个，缓存到内存后写入本地磁盘

4）中间数据分区和存储

例：3个Map任务将数据块分为了4个大类别，这就是4个Reduce类别。

中间数据按 R 个分区函数（比如按 key 哈希）划分，写入本地磁盘，并把位置报告给主节点，主节点再通知 Reduce 节点去哪里取数据

5）Shuffle & Reduce 读取数据
  • Shuffle（拿Map分类好的数据）
  • Reduce（对哪来的数据排序）
6）Reduce任务 - 汇总+输出（后）

人话：汇总每个大类有多少个，将结果写道汇总表里

Reduce 节点遍历排序后的中间数据，对每个唯一的 key 调用 Reduce 函数，将结果写入最终输出文件

7）完成任务

所有 Map 和 Reduce 任务完成后，主节点通知用户程序，返回最终汇总结果

二、实践任务

修改：coordinator.go、rpc.go、worker.go 三个文件

简单流程解析：

worker向coordinator请求任务（通过rpc），包括：map或者reduce任务，coordinator将剩余任务分配给worker处理（先处理完map任务才能处理reduce任务）

该实验中：

  • map任务数量 = 输入文件数量

  • 每个map task的任务为处理一个.txt文件

  • reduce任务的数量 = nReduce

  • Map任务将文件内容分割为指定的nReduce份，每一份由相应序号标明

  • 拥有这样的序号的多个map任务的输出汇总即为对应reduce任务的输入

  • 处理完任务，worker告知coordinator结果（通过rpc）

综上：
  • coordinator管理任务状态和任务分配，无需记录worker信息
  • worker实现任务处理
